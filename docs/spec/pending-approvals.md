# 未承認事項（ユーザー承認待ち）

本ファイルの内容は**承認済み仕様ではない**。承認が得られた項目は DEC を発行し、`docs/decisions/adopted-decisions.md` と `mvp-spec.md` を更新する（DEC-038/041）。
承認前の実装は「安全な暫定動作」の範囲に限り、根拠のない `ACCEPT`（成功扱い）をしない。技術上の型・API・テスト・試験用係数は Claude Code が判断してよい。

## 1. 判断ゲート（ゲーム規則の追加に承認が必要）

Gate に抵触する新しい振る舞いが必要になった Issue でのみ、推奨案の採否を確認する。初期の型・reducer・分岐・年代記・明示契約フィクスチャの作業は止めない。

| Gate | 争点 | 推奨案（未承認） | 承認前の安全な実装 |
|---|---|---|---|
| GAME-01 | 新規婚姻契約の子の法的王朝帰属 | 有効契約の明示条項を優先、特約なしは父系帰属とするか | 既存の有効な明示契約からのみ認定。未指定は `UNDETERMINED`。父系条項を自動生成しない。出生・親子記録自体は作れる |
| GAME-02 | 法的承認の権限者と裁量審査の範囲（婚姻・通常土地相続・王位・剥奪・外国封臣） | 既存の授与条件で後継が一意かつ追加承認不要な場合のみ機械処理、他は PENDING | 承認根拠・必要権限・証拠のフィールドと事前審査 API。証拠が揃う場合のみ ACCEPT、他は PENDING/REJECT。権限を後付けしない |
| GAME-03 | Title 相続後の代理統治の継続、主権変更後の旧承認の効力 | 歴史は消さず、新受益者への委任・新宗主下の承認は新根拠がある場合のみ有効。敗戦だけの一律剥奪は禁止 | 委任受益者を自動付替えしない。新宗主への旧承認は `REQUIRES_RECOGNITION` とし勝利根拠にしない |
| GAME-04 | 占領・反乱後の翌年度の収税先と徴収不能の意味 | 有効契約があれば一国にのみ配賦。根拠不明なら占領者へ配賦しない | 6 地域の当初 TaxCollectionMandate を明示。当年税収を遡及変更しない。根拠不明は `UNRESOLVED_TAX_AUTHORITY`（診断のみ） |
| GAME-05 | 反乱・戦争による地域支配移動の詳細（軍事比率・戦闘閾値・「1 年 1 地域」等） | 「1 年 1 地域」の固定上限は設けず、競合時は明示的な戦闘結果を原子的に処理 | ForcePool/ResourceLedger・Conflict・支配変更の型と安全チェックまで。制限や占領効果を規則として追加しない。試験係数は `CALIBRATION_ONLY` |

**2026-11-03 の部分採用（DEC-055）:** GAME-01 は「有効な明示条項があるときのみ確定、欠落は UNDETERMINED（父系既定値なし）」、GAME-02 は「権限者・授与条件・証拠が明示され後継が一意で追加裁量不要なときだけ機械処理」、GAME-03 は「旧委任受益者を自動付替えせず、新しい明示根拠の委任を別に扱う」までが採用済み。

**通常ケースの限定決定（DEC-057）:** GAME-02の同一国家内通常婚姻および世襲土地相続の認証者は、当該管轄/現行主権国家の法制機関（`COUNTRY`）。GAME-03の新規統治委任の発行者は当該地域の現在の実効統治者（`deFactoControllerRef`）、国内の国家直轄なら同じ`COUNTRY`。どちらも、その者が存在するだけでは権限は成立せず、**事前の法令・授権記録と、当年の対象・意思・法的根拠の一意な審査**が必要。詳細は `docs/spec/mvp-spec.md` §8。発行可能な権限を1250年の仮データへ追加する場合は出典・`experimental`を記録し、固定イベントによる原史敗北・成功を作らない。

**MVP次世代の限定具体化（DEC-058 / Issue #71）:** 同一国家内の次世代の国内通常婚姻は、年初生存・双方満18歳・現行B-002父母モデルに対応する男女ペア・有効婚姻重複なし・共通管轄と法的授権が必要。記録された直系祖先/子孫および双方2世代以内の共通祖先を禁親とする。B-005の交渉では本人相互の婚姻相手の選択と、契約案ごとの双方同意を分ける。案は無条項または実際にDETERMINEDな当事者の王朝への明示条項で、**双方が同意し、校正用の相互利益スコアが一意最大の案**だけ契約登録候補にする。衝突・同率・合意不能はDEFERであり、勝利のための王朝案の自動選択は禁止。出生児・根拠付きB-001昇格人物にも年次適用する。具体的な相互利害スコア重みはCALIBRATION_ONLYとし、法的婚姻・子の王朝・出生・Goalは直接介入しない。詳しくは`docs/spec/mvp-spec.md` §8.1。

**人口集団からの補助婚姻候補供給（DEC-061）:** ユーザーは「婚姻可能な人間を重要人物の登録人数だけに限定せず、人口集団から非操作対象の補助人物を供給する」設計方向を明示採用。重要人物の増加率と補助配偶者の抽出は別の仕組みとする。具体的な有力層の階層比率、出生年/性別コホートの初期分布、家門/血縁証拠の粒度、抽出数・婚姻効用スコアは**正式には未確定**で、初期実装の試験値は`CALIBRATION_ONLY`。総人口から特定個人の名前や近親非該当を推定したことにはしない。婚姻成立後の補助人物は法的に追跡可能である必要があるが、プレイヤー介入対象には自動昇格させない。

**引き続き未承認:** GAME-01の無条項時の子の父系帰属（UNDETERMINED維持）、GAME-02の王位・剥奪・外国封臣・国際婚姻の権限、MVPで扱わない離婚・宗教/身分差・国際・歴史的年齢法、Claim争訟、GAME-03の主権変更後再承認・外国委任、B-001の出典不足時の人物生成、1350年の正式Goal公開条件、初期法令・Title・人物配置の正式設定。未記録の証拠を作り、根拠のない`ACCEPT`を出すことは禁止する。

**「年間 1 地域のみ支配が移る」案は採用されていない。** G-15 相当の後続判断として保留。

## 2. データ不足（資料に具体値が無い）

DEC-014 は初期世界の規模を採用しているが、次の具体値は移行資料に含まれない。Claude Code は創作で確定せず、`experimental` の試験用フィクスチャ（出典と「仮値」を明記し、正式な世界設定と誤表示しない）として実装し、正式化にはユーザー承認を要する。DEC-032/033/038 と 08 v0.4 に基づき、技術・校正用の暫定データとしての実装は可能。正式なシナリオ設定への昇格にはユーザー承認が必要。

- 初期重要人物 8 人の氏名・生没年・続柄・称号・性格値（紙上プレイの候補名はあるが生年・親子関係に矛盾があり得る）
- 6 地域・10 集団の人口・生産・不満・家門支持分布・隣接関係の具体値（国庫 45/100、正統性 50/100、不満 西 70/東 55/南 35 のみ既知）
- 家門間関係、初期の称号・授与根拠・TaxCollectionMandate、各国の財政・軍事の初期値
- 世襲所領を持つ Title の初期配置（勝利条件の判定対象）

## 3. 実機で調整する係数（ゲーム規則の採用ではない）

出生・自然死率、人口の出生/死亡分解、重要人物の昇格率、信頼/政策/利益スコア、税率・生産・天候確率・税→BU 換算・国庫単位、支持信号 scale、不満減衰、動員率・戦闘優勢・損耗・外交効用、数値介入の既定補正量/期間。

## 5. 移行時に採用しなかった提案

次は移行元の未承認提案であり、仕様・契約に昇格させていない。

- 新規婚姻の父系を無条項の既定とする案（GAME-01）
- 敗戦・占領時に占領者へ税を自動移管する案（GAME-04）
- 国庫 45/100 = 45BU とする断定案
- 旧 C-008 の毎年 +100 均等化、旧 C-006 の 1BU 自動再配賦
- RuleOutcome を自由な `fieldPath` 書き換えとして実装する案（危険のため回避。`docs/contracts/` の判別可能な Command union を使う）
- 過去年への介入で同年の既存介入まで破棄する案（DEC-023 違反）
