# シミュレーション開発・検証の実践ガイド（DEC-159）

> 目的：ChatGPT、Claude Code、独立レビュアーが、新しいチャットや作業セッションでも同じ基準でシミュレーションを実装・受入できるようにする。
>
> 適用：ユーザーが採用した「目的に適合した最小限の因果モデルを定義し、実際の振る舞いを検証してから拡張する方式」の実務手順。ゲーム規則の正本は `docs/spec/mvp-spec.md`、技術責務は `docs/contracts/mvp-implementation-contract.md`、採用判断は `docs/decisions/adopted-decisions.md`。本書で新しいゲーム規則・勝利条件・固定テスト件数を追加しない。

## 0. 最短の実行手順

1. **目的を一つ決める。** プレイヤー体験に必要な、観測可能な現象を一つ選ぶ。
2. **因果鎖を作る。** 状態・主体・外部入力・判断・権限・確定結果・翌年への伝播を必要最小限に整理する。
3. **先に受入条件を決める。** 正常成立、正当な不成立、欠落してはならない証拠・不変条件、時間的な継続を区別する。
4. **最初の欠けた接続を実装する。** 既存の共通ルール、実評価器、reducer、ID/RNGを再利用する。
5. **実経路をRED→GREENにする。** Unitだけでなく通常の年次runner、EventLog、DecisionTrace、WorldStateで検証する。
6. **別条件で反証を試みる。** 他の人物・年・seed・枝・試験入力で再実行し、固定成功ケースへの過適合を検出する。
7. **結果と未実証範囲を分けて報告する。** 局所実装、縦断、長期挙動、介入、人間の試遊は別の合否とする。

正当に婚姻や相続が成立しないこと、あるseedで王朝が断絶することは、それだけではバグではない。**「なぜ成立しなかったか」を採用済み規則と実記録から説明できるか**が重要。

## 1. 実装前の最小モデル定義（別文書の新設は不要）

ODD Protocolの「Purpose and patterns」「Entities, state variables and scales」「Process overview and scheduling」を短いモデルカードにする。IssueまたはClaude Code委任の冒頭に以下を埋めればよい。

| 欄 | 書く内容 |
|---|---|
| 目的と境界 | 何の現象が必要で、今回は何を対象外にするか |
| 一次状態と粒度 | WorldStateで保持する値、人口等の集計、一時ビュー、派生値の区別 |
| 処理順序と責任 | 入力 → 評価器 → 法的/資源審査 → Command → reducer → 翌年。実際のRuleIDと書込owner |
| 判断の根拠 | 当年/当枝の出典、権限、同意、保存則、不確実性、証拠欠落の扱い |
| 成立パターン | 何が起きればその機構が成立したと言えるか。状態・Trace・Eventで観測可能にする |
| 否定パターン | 正当なDEFER/REJECTと、不正な成功・部分確定の禁止 |
| 一般性と受入 | 別の人物・年・seed・枝で何を試すか。今回閉じるゲート |

例：婚姻・出生・世代交代では「実出生者 → 生存・成人 → 候補選択 → 双方の意思 → 法的承認 → 婚姻登録 → 次の実出生 → 法的王朝判定」。最初の夫妻の成功だけでは、成人した子が再び候補となる継続経路の証明にはならない。

モデルの目的に必要ない全人口の個別化、細かな歴史制度、複雑な係数は先行しない。ただし**必要な因果機構そのものを省略して成功例で取り繕うこともしない**。

## 2. モデル実装の原則

- **判断と確定を分離する。** 候補提示・意図・合意・適格性確認は別段階。正当な権限と検証済みCommandを通さずWorldStateを変更しない。
- **一次値と証拠の所有者を一つにする。** 集計人口、個別人物、一時候補、出生枠、法的状態、ログを二重計上・混同しない。
- **時間を契約として扱う。** 年初/年内、当年・翌年、枝、処理順、証拠の有効期間を明示する。前の年や別枝の承認を無審査で再利用しない。
- **欠落は成功で埋めない。** 親ID不明や家門差を非近親証明としない。証拠不足は適切にDEFER/PENDING/拒否し、理由をTraceに残す。
- **結果を直接作らない。** 婚姻・出生・相続・勝利を特定人物・特定年で強制しない。テストの成功Commandを実年次成立の代用にしない。
- **決定性と隔離を設計時から守る。** 正本の安定ID・RNGキー・seed・ルール版・介入ledger・年・枝の契約を使用。巡回順や共有可変キャッシュで別の計算を汚染しない。
- **CALIBRATION_ONLYと共通モデルを区別する。** 試験用の独立した出典・信頼・係数は機構の成立可能性の実証には使えるが、その成功だけで一般的な発生頻度を主張しない。
- **既存規則との衝突を先に見つける。** 技術的な接続・テストの問題はClaude Codeへ委任してよい。新しいゲーム規則・勝利条件・重要体験方針・正式世界設定は別途ユーザー判断を得る。

## 3. 検証ゲートと完了判定

| ゲート | 検証 | 受入証拠 | まだ言えないこと |
|---|---|---|---|
| G0 モデル定義 | 目的、状態、必要な因果鎖、正当な不成立を説明できるか | モデルカードと明示AC | コードが正しい |
| G1 Verification | 局所規則、型、境界、不変条件、原子性 | Unit/Property/否定テスト | 実世界の因果鎖が通る |
| G2 縦断成立 | 通常評価器と実年次runnerで状態が合法に更新されるか | 実WorldState・EventLog・DecisionTrace・request/Commandの連結 | 長期継続する |
| G3 ライフサイクル | 年跨ぎ・死亡・再婚・成人・世代更新が繋がるか | 生まれた人物が成長・婚姻・次の出生へ到達する実記録 | 別条件でも十分成立する |
| G4 振る舞いの妥当性 | 複数人物・コホート・seed・年でどのような分布と不成立理由が生じるか | 機会数、各段階の成立/DEFER、長期指標、反例 | 全seedで勝利する |
| G5 介入への応答 | 同条件のA0/A1で数値補正が判断・Event・後年状態へどう届くか | 実因果経路と、変化がない場合の根拠 | 介入で必ず結果が変わる |
| G6 人間の評価 | 成立した中核メカニズムの上で探索・介入・比較が面白いか | 人間の試遊観察 | 自動UIテストだけでは評価不可 |

**ゲートは作業領域に応じて適用する。** 軽微な表示修正でG0〜G6全体を再実行しない。ただし「世代更新シミュレーション完成」と称するなら、その責務のG3/G4が未実証のままではならない。大規模なG4/G5をG2の代わりに先行して、失敗地点を埋もれさせない。

## 4. テスト戦略（「何を発見するか」に合わせる）

| テスト層 | 主な発見対象 | 方法 |
|---|---|---|
| 局所Unit | 条件分岐、法的適格性、境界、理由コード | 実装規則の肯定/否定/DEFER、境界値 |
| Property-based | 入力の組合せ、参照・保存則、重複・競合 | 既存fast-check等で有効データ生成。反例のseed・pathを保存して縮小 |
| Metamorphic | 結末の唯一正解がなくても成り立つ関係 | 同一入力・版・seedの再計算一致、違法操作で状態不変、別枝不変など |
| 実縦断 | 評価器・法的審査・Command・reducerの断線 | 実runYearでIDとTrace/request/response/Command/Eventを照合 |
| ライフサイクル | 成人到達、死亡、契約、次世代の継続 | 短い年跨ぎから親→子→孫の必要期間まで伸ばす |
| 長期実験 | 固定成功例への過適合、供給断絶、分布や遅延 | 固定回帰seed＋独立探索seed、複数入力、係数感度、理由別分母 |
| 分岐/E2E | 介入効果、データ混線、表示の偽装 | 同じ世界のA0/A1実再計算、UIは実状態・Trace/Eventと照合 |

**テストオラクルを区別する。**

- 不変条件は厳密に判定する：人口保存、重婚禁止、親子循環禁止、法的権限、原子性、同条件の決定性。
- 部分的な関係を判定する：具体的な違法ペアは法的承認されない、証拠欠落は成功と扱わない等。
- 目的に関連したパターンを観察する：生存する成人が候補となり得る、婚姻から次世代出生が成立し得る、複数年でも機会が継続的に供給され得る。
- ゲーム性は別に評価する：理解・好奇心・介入動機・予想外の変化の魅力を、AIテストのPASSだけで代用しない。

**誤ったメタモルフィックassertを避ける。** 「信頼+10なら必ず婚姻件数増加」「ある候補を消すと総婚姻数が必ず減る」は、競合や代替選好があるモデルでは一般に保証されない。入力変化に対応する局所判断や明示的な不変条件のみ厳密assertし、遠い最終結果には実測と説明を用いる。

**失敗時はassertを緩めない。** 失敗の最小入力、元の契約、actual reasonCodesを確認する。旧仕様テストの変更が必要なら検証目的と重要な否定条件を移行する。単にskip・削除・成功fixtureへの変更だけでGREENにしない。

## 5. 長期実験と診断指標

「100年で婚姻4件」だけでは原因が分からない。**件数の分母と脱落段階**を記録する。

1. **機会:** 出典のあるコホート人数、成人・生存・管轄の適格者、異なる候補ID、再提示回数、供給不足。
2. **探索・選好:** B-001提示、B-004採否、B-005双方の一意最優先・同率・不一致・信頼不足。
3. **法的判定:** A-LEG-01照会、承認・拒否・DEFER、禁親・重婚・証拠・授権・管轄などの理由。
4. **確定・継続:** 実婚姻、出生枠、実出生、死亡、翌年再婚、子の成人・婚姻・孫、法的王朝と相続。
5. **終点:** HALTED、最大世代、生存する追跡人物、1350年Goal、同条件再計算の差分。

「同じ候補が6年提示された」は6人ではない。人物数・ペア数・候補提示回数・年数を区別する。成功したseedだけでなく、異なる結果のseedとDEFER理由も報告する。

**実験の段階**

- 固定seedは回帰検出用。少数の固定seedから「一般的な婚姻率」を推定しない。
- 新しい独立seed・初期条件で機構の一般性を試す。使用したseed集合、サンプル数、計算予算を記録する。普遍的なseed件数や成功率を本書で固定しない。
- 機構が成立した後に少数のCALIBRATION_ONLY係数の感度を比較する。**構造的欠陥をパラメータ調整で隠さない**。同時に複数の入力要因を変更した比較を単一要因の効果と断定しない。
- 同じ出発点・seed・ruleset・法制・RNG・介入ledgerの違いを記録してA0/A1を比較する。介入以外の差も明示する。差分だけで因果を断定せず、評価器の判断Traceまで追う。
- Goal達成率を上げるために規則やGoalを緩めない。正当な断絶もシミュレーション結果として尊重する。

## 6. 不成立・HALTEDからの診断順序

| 観測事実 | 次に確かめるもの | 禁止すべき近道 |
|---|---|---|
| 年次HALTED | 年・Phase・Rule・理由、直前のTrace/Command、原子性 | 最終ガードの無条件削除 |
| 候補提示0 | コホート、人数、年齢、生存、管轄、抽出予算、出典 | 人口を無条件追加する |
| B-004/B-005でDEFER | 相互順位、同点、信頼根拠、他候補、個別証拠 | ID順に配偶者を選ぶ |
| 法的照会でDEFER/拒否 | 当年・同枝の権限、禁親・重婚・契約・証拠 | 不明な血縁を非近親と推定する |
| 婚姻後に出生なし | B-002、C004枠、年齢、生存、婚姻期間、出生Trace | 年固定の出生イベント |
| 出生後に世代が続かない | 成人到達、候補探索への再参加、死亡、次世代証拠・関係入力 | 初期夫妻だけの成功例を追加する |
| 年次完走でもGoal未達 | 合法王朝、Titleの有効性、実効支配、後年の継続、介入差 | Goalや勝利フラグ変更 |

原因は実測で確定する。分類は **(A) コード不具合、(B) 必要なモデル機構の欠落、(C) 試験用出典/証拠の不足、(D) 世界内の正当な不成立、(E) 係数・分布の問題**。

- A/B：欠けた共通機構を最小修正、実縦断と回帰を追加。新しいゲーム規則が必要ならユーザー承認へ戻す。
- C：必要な独立したCALIBRATION_ONLY供給を出典つきで追加可能。ただし「試験環境では成立可能」と「自律的に普遍成立」は分ける。
- D：結果は変更せず、他の合法な機会があるか実測する。
- E：モデルの構造を確かめた後、感度・分布・プレイヤー体験の目的から必要な校正だけ行う。

## 7. ChatGPTとClaude Codeへの委任・修正反復

**一つの委任は一つの観測可能な因果鎖または失敗ゲートを閉じる大きさにする。** 大量の「設計、100年、全E2E、全レビュー、全PR」を毎回まとめて指示し、部分調査で終了することを繰り返さない。逆に小修正は分解しすぎない。

ChatGPTがClaude Codeへ渡すときの必要項目：

- **対象:** repo、Issue/PR、正本、worktree/branch、現在のHEAD、保護すべきdirty差分。
- **目的:** 今回成立させる現象、対象ゲート（G0〜G6）、不足している因果鎖。
- **Allowed Paths:** 編集者と共有APIの所有者、他担当の保護対象、未承認のゲーム規則。
- **受入:** 実runnerでの正常ケース＋禁止/DEFERの反例、WorldState/Trace/Eventの整合、年・枝・seed・ルール版。
- **実行:** 失敗の実測→最小変更→関連テスト→修正再試行→必要な回帰→独立レビュー→証跡回収。
- **停止:** 権限外編集、未承認仕様判断、実行不能な環境障害。通常のテスト失敗だけで放棄しない。
- **報告:** 各ゲートのPASS/FAILED/UNVERIFIED、具体的な再現手順、最終HEAD、残件と次に閉じるゲート。

共通のfreshセッション管理、SubAgent、worktree、PR/CI手順は正式ChatGPT Skill `claude-code-delegation` に従う。このガイドにそれらの共通ルールを複製しない。編集担当は共有APIの編集を一人へ集約し、独立レビューは最終差分の実証拠で判断させる。

**反復の終了**

- **PASS:** 今回指定した小ゲートを実証。別の上位ゲートがUNVERIFIEDなら未完成として残す。
- **FAILED:** 承認された範囲で修正可能なら同タスク内で修正・再検証。新規判断が必要なら該当箇所だけ明示。
- **BLOCKED:** 権限外の変更、破壊的副作用、アクセス不可等の具体的障害。可能な独立作業は継続。
- **PR:** 変更対象HEAD、独立レビュー、 `quick-check`、人間の明示的なmerge承認を別々に扱う。

## 8. 最小の再現・引継ぎ証跡

新しい台帳やJSONスキーマは必須ではない。既存Issue/PRコメントやテスト証跡で以下を残す。

| 項目 | 保存するもの |
|---|---|
| 対象の現象 | 目的、モデルカード、Gゲート、成立・否定AC |
| 正確なコード | repository、最終commit/ Git tree、dirtyの有無、テストコマンドとexit code |
| 再計算条件 | scenario/config digest、ruleset/legal/rng版、seed、対象年、branch、介入ledger、出典 |
| 判断連鎖 | 年・RuleID・reasonCodes、候補/人物ID、Trace、request/response、Command、Event |
| 実測 | 機会と分母、各段階の成立/DEFER、婚姻・出生・最大世代・存命人数・Goal |
| 健全性 | 人口・資源保存、重婚・親子・権限、年の原子性、再計算一致、枝隔離 |
| 判定 | Unit/CI、縦断、長期、介入、review、本人試遊を個別にPASS/FAILED/UNVERIFIED |
| 次工程 | 確認済み原因と仮説を分離、残る一つの因果鎖、必要な最小の承認 |

作業中の未commitコードで出したPASSを、別の最終commitのPASSとして流用しない。古いHEADのCIは新差分の検証ではない。元worktreeに保護対象があるときは、内容ハッシュが一致する隔離コピーでテストするなど、書込安全性を確認してから実行する。

**検証頻度:** 小変更では関連Unit/Property/縦断を優先。関連ゲートが安定したら `npm run check` と必要な `npm run test:e2e`、独立レビュー、最終HEADの `quick-check` を実行。100年・独立seed・感度・性能はモデルの節目で実施し、すべての些細な編集で繰り返さない。

## 9. 典型的な迷走と防止策

- 「成功例が1件ある」→ **一般性の証拠ではない**。次世代・別条件・不成立を調べる。
- 「CIがGREEN」→ **Verificationの一部**。実年次・長期モデルの妥当性は別。
- 「DEFERが多い」→ **即バグではない**。理由・機会・出典・適格者数を分解する。
- 「今の世界では勝てない」→ **Goalを緩めない**。合法王朝、Title、支配、介入の実因果を調べる。
- 「テストだけ変えればPASS」→ **検証の弱体化を禁じる**。契約と反例を保持する。
- 「全個人をモデル化すべき」→ **目的に必要な粒度だけ**。不足した機構を出現回数の調整で隠さない。
- 「Claude Codeが調査だけで終了」→ **対象ゲートが閉じたか判定**。未達で実装可能なら次の小修正へ進む。
- 「人間がまだ面白くない」→ **前提の切り分け**。中核シミュレーション成立前の操作性評価を面白さの最終判断と混同しない。

**シミュレーション領域の完了とは：** 対象現象が承認済み規則で実際に成立し得ること、正当な不成立や禁止行為も同じ共通経路で扱えること、年・世代を跨いで継続し得ること、代表的な異条件で致命的なモデル欠落が見つからないことを実証した状態。一般性・分布に関する未確定事項は明記する。全seedが同じ結果になることやGoal達成は要求しない。人間の面白さの最終評価は、この中核が成立した後に別途行う。
