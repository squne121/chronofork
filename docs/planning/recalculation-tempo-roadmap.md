## 何を改善するか

介入から新しい世界線の生成・閲覧までの**実時間**と**体感待ち時間**を区別して短縮する。`WorldState`、`EventLog`、`DecisionTrace`、決定的なseed/乱数・履歴比較・HALTEDの診断を破壊しない。演出を強制再生して完了を遅らせない。ゲームエンジン変更を前提にせず、UI/Workerと純粋なシミュレーションを分ける。

2026-11-08時点の確認事項（計測結果の再検証は別途必要）:
- `main` `505376e75d7206b2a9f7a5b4a15ad210979b303e` に統合試遊Worker（PR #91）がある。`src/ui/play-worker.ts` は計算と表示ビューへの変換後に結果を送信し、年次進捗イベントは未実装。
- `src/ui/branch-play-source.ts` の統合比較は各操作でA0を1250年から生成し、`forkHistory`で介入年以降のA1を再計算する。
- `src/simulation/branching/fork.ts` は介入以前の年初snapshot/Event/Traceを保持して残りを再計算する。Checkpoint/Forkの基礎は既存。
- PR #90の報告では、100年長時間試験の主要ボトルネック短縮により649秒→40秒、出力SHA一致。**現在の実機・ブラウザUIの時間として一般化しない。**

## MVP完成後の候補と検証

1. **歴史生成タイムラプス（UX候補 / DEC-071）:** 計算済みの年・実際の事件・地域や家系の変化を段階的に表示。演出・スキップ・速度制御を計算と分離する。`WorldState`/`EventLog`/`DecisionTrace`に存在しない出来事を演出で追加しない。現時点では具体UI実装は採用未確定。
2. **依存関係追跡・増分再計算（技術検証先行 / DEC-070）:** `RuleID`/読み書き対象/年境界/乱数キー/法制・相続・人口集団の波及を明示し、「影響なし」を証明できる最小処理から試作。参照全計算との同値性（最終状態だけでなくEvent/Trace/診断・ID・順序も含む）と計算費用をseed・介入年を変えて比較。静的な距離や人物数のみで他処理を省略しない。証明不能なら従来の全suffix再計算へfallback。
3. **製品版の新規世界生成とプレイヤー保存（上位要件 / DEC-068）:** 新規プレイ開始ごとに新しい世界を構築し、気に入った世界を明示保存できるようにする。ゲーム内の同一世界に対する介入はCheckpoint/Forkを継続利用できる。何が毎回変化するか（地理・人物・制度・初期条件等）、seed/ID、保存対象（原史・改変史・介入台帳等）、閲覧/再開/互換性/容量は未決で、別途ゲームデザインの承認を得る。MVPの固定世界・固定seed仕様は変えない。

## エンジン移行への独立性

- シミュレーションの進行・Checkpoint/Fork・依存関係・データ検証と、React/Worker/将来のエンジンUIを分離する。将来のゲームエンジン名・言語・Rust/WASM化はこの決定で確定しない。
- リプレイ/保存の互換性に備え、seed・world/scenario・ruleset・legal・rngの版、介入台帳・ログ・チェックポイントの識別条件を設計時に明示する。正確な保存契約の決定・実装は将来タスク。
- 最適化が歴史の真正性を犠牲にしないことを最優先する。
