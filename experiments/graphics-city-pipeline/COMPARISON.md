# 都市制作経路の比較

共通 Three.js 側が地形・橋・配置を担い、両経路は建物部品を制作する。都市全体を Blender で作る方式の比較ではない。`STATUS.md`、`C0-REVIEW.md`、`C2-BENCHMARK.md` も参照。

## 初期費用

| 項目 | A: Blender | B: Three.js |
|---|---|---|
| 初期制作の合格所要時間 | 未取得 | 未取得（単体形状のみ82秒、C0合格時間ではない） |
| 環境導入 | 公式5.2.4を照合・ローカル展開。不足ライブラリの追加承認とローカル展開が必要だった | 実験依存を npm で導入 |
| 初回再生成 | 実 Blender GLB/.blend 生成の壁時計1.84秒。初期制作費ではない | 初期制作時間への換算不可 |
| C0 | 最低品質 PASS。橋端段差は共通基盤の留保 | 同左 |

## 継続修正・検査

| 項目 | A: Blender | B: Three.js |
|---|---|---|
| C1 | 色・寸法の局所更新と再適用を検査範囲で PASS | 同左 |
| C2 初回受領〜単体確認 | 約2分06.6秒。実 Blender による部品生成を含む | 約1分45秒。npm ci を含む観測区間で、制作時間だけではない |
| C2 再実行（各3回） | 0.517426 / 0.463380 / 0.470276 秒。3 GLB と .blend 保存を含む | 0.076350 / 0.060946 / 0.065534 秒。3形状生成と JSON 保存を含む |
| C3 | fresh 担当が再生成し、tiered を含む別配置・局所変更を検査。詳細は `c3-handoff.txt` | 同左 |

C2 の数値は異なる処理と出力を含み、同等作業の速度順位ではない。担当受領時刻は最初の観測時刻で、統合検査・差戻し・環境導入の厳密な按分はできない。共通基盤・検査の費用は経路固有費用に含めない。A/B 担当は環境表示 `gpt-6.1-terra`、effort は未確認。

人間の理解・好み・確認時間は未確認。比較件数は一例であり、普遍的な優劣や統計的優位は主張しない。現段階の推奨は **判定保留**。今後、通常建物は直接生成・特徴的な部品は Blender という併用も候補だが、人間確認と異なる処理範囲の費用評価が終わるまで採用を推奨しない。
